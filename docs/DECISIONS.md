# Penknife — decisions and lessons

- **Name**: Penknife (English, free on Mac app stores; Google shows a folding pocket knife, matching the logo idea).
- **Signing**: free self-signed certificate in the login keychain for stable permissions; paid Apple Developer account later, when publishing several apps. Never the "Apple Development" certificate for installed builds (see the `macos-build-sign-install` skill).
- **Prior art to reuse** (all from 2026-11-12, dotfiles repo and fork `alexl-l/MTMR` branch `touchbar-custom`):
  - Touch Bar via private DFR APIs as in MTMR (`presentSystemModal`, `minimizeSystemModal`); MTMR is MIT — check obligations with `legal-advisor` before copying code.
  - Keyboard backlight: CoreBrightness `KeyboardBrightnessClient` (`setBrightness:forKeyboard:`); disable `enableAutoBrightness:forKeyboard:` on manual change, or a bright room keeps the light off.
  - Display brightness: DisplayServices `DisplayServicesSetBrightness`.
  - CPU temp: AppleSMC user client, key `TCMb` (`macos/mtmr/mactemp.c`).
  - Dialog detection: Accessibility; real dialogs = `AXSheet` role, `AXSystemDialog` subrole or `AXModal`; check only the focused window and focus chain; drive it with AX observers (`AXFocusedWindowChanged`, `AXFocusedUIElementChanged`, `AXWindowCreated`, `AXSheetCreated`), not polling.
  - System prompt apps: SecurityAgent, UserNotificationCenter, coreservices.uiagent, LocalAuthentication.UIAgent, CoreLocationAgent, accessibility.universalAccessAuthWarn.
- **Token-heavy verification** (screenshots, logs) goes to the `qa-tester` agent.
- **Minimum macOS 26** (2026-11-13): the user's Mac runs 26.6; supporting older versions adds testing and code paths for no gain in a personal app. Touch Bar Macs (M1/M2 13" MacBook Pro) run macOS 26. Revisit if published and users ask.
- **Mac App Store not viable for the full app** (2026-11-13): App Review rejects private APIs (guideline 2.5.1) and the sandbox blocks controlling other apps. Penknife depends on private DFR (Touch Bar), DisplayServices/CoreBrightness (brightness), AppleSMC (temperature) and Accessibility/event posting (dialogs, jiggler, F keys). Store version would lose most features. Proposed path: notarized Developer ID download + Sparkle (MIT, standard for non-store apps); Sparkle is forbidden inside the App Store anyway.
- **No paid Apple Developer account** (2026-11-13, user's decision): rules out WeatherKit, notarization and the Mac App Store. Sparkle still works (own EdDSA keys).
- **Private APIs can't be removed** (2026-11-13): a menu bar app is never frontmost, so public `NSTouchBar` never shows; only private DFR gives a global Touch Bar. No public API sets built-in display or keyboard backlight brightness on Apple Silicon (only simulating brightness keys, which gives steps, not a slider). Outside the App Store private APIs are allowed; the risk is that a macOS update breaks them, so each one lives behind its module (R-15) and fails gracefully.
- **Public repo hygiene** (2026-11-13): git author is `alexl-l <53312543+alexl-l@users.noreply.github.com>` (history rewritten, repo-local config set); `.gitignore` excludes builds, xcuserdata, certificates and secrets. Never commit keys, certificates, personal paths or emails. License pending (MIT likely; check MTMR obligations with `legal-advisor`).
- **Accessibility**: global `accessibility-reviewer` agent reviews every UI change (R-19).
- **Shortcuts: KeyboardShortcuts library** (sindresorhus, MIT; 2026-11-13): native recorder control, keyboard and VoiceOver accessible, avoids writing our own. Add its license notice to the app.
- **Weather: Open-Meteo** (2026-11-13): free for non-commercial use, no key (nothing secret in the repo), data CC BY 4.0 (attribution required). If Penknife ever becomes commercial, check their terms with `legal-advisor`.
- **Project setup** (2026-11-13): hand-written Xcode project with a synchronized `Penknife/` folder (new files need no project edits), Swift 6 with MainActor default isolation, AppKit `NSStatusItem` + `NSMenu` (native keyboard menu) and SwiftUI views inside an `NSTabViewController` toolbar window for Settings (the SwiftUI `Settings` scene can't be opened reliably from a menu bar app). String Catalogs for es/en. Bundle id `io.github.alexl-l.Penknife`.
- **Signing certificate created** (2026-11-13): self-signed "Penknife Local Signing" (10 years) in the login keychain, trusted for code signing. `scripts/install.sh` builds Release, signs with it (hardened runtime) and installs to /Applications. The private key exists only in the keychain.
- **Jiggler without event tap** (2026-11-13): reads system idle time (`CGEventSource.secondsSinceLastEventType`) and sleeps with a one-shot timer until the next jiggle could be due; no Input Monitoring permission, ≤1 wakeup per ~10 s while on, none while off. Same movement as Hammerspoon (3 px square + Caps Lock twice).
- **Lock screen** (2026-11-13): private `SACLockScreenImmediate` (login.framework, what the Apple menu uses, no permission); falls back to posting ⌃⌘Q.
- **Menu shortcuts paused while the menu is open**: KeyboardShortcuts requires it (events get buffered during menu tracking).
- **Hammerspoon coexistence**: both register the same F keys; only one gets them. Quit Hammerspoon to use Penknife's shortcuts; MTMR still depends on it for music and dialogs until phase 2.
- **Launch at login only from /Applications** (2026-11-13): the first registration came from the Debug build in `build/`. Now only the /Applications copy registers, and it re-registers if its path changed. The user's choice is stored separately (`launchAtLogin.enabled`, default on).
- **Settings window built on open, released on close** (2026-11-13): SwiftUI tabs took RSS from ~15 MB to ~60 MB. Idle: 0 % CPU, 0 wakeups, ~11 MB footprint.
- **Accessibility prompt once per launch**: actions that need it don't re-prompt on every press; Settings → General has the button.
- **Meet sync matches `https://meet.google.com/` by prefix** so no other tab gets the script. Known limit: it relies on the English aria-label "Turn on microphone".
- **QA agents can't drive the UI** unless their shell (Terminal/Claude) has Accessibility; hands-on UI checks fall to the user or need that permission.
- **F keys from the Touch Bar carry Fn** (2026-11-13): KeyboardShortcuts strips Fn, so a bare "F12" never fired from the Touch Bar (the old Hammerspoon binds used `fn`). `Core/FnHotKeys.swift` registers an F key + Fn twin (Carbon `kEventKeyModifierFnMask`) for every bare F-key shortcut, refreshed when shortcuts or modules change.
- **Jiggler follows the lock** via `com.apple.screenIsLocked` / `screenIsUnlocked` distributed notifications, observed only while the module and option are on.
- **Hotkey de-duplication** (2026-11-13): a Touch Bar F key fired both the plain and the Fn hotkey, flipping toggles twice; actions now run at most once per 0.4 s (`ModuleManager.run`).
- **Stale Accessibility grant** (2026-11-13): System Settings showed Penknife on, but the grant belonged to an older (ad-hoc) signature. Fix: `tccutil reset Accessibility io.github.alexl-l.Penknife` and grant again. With the self-signed certificate the designated requirement is stable, so grants survive reinstalls.
- **Touch Bar presentation** (2026-11-13): private calls looked up at runtime (`dlsym` for DFRFoundation functions, `class_getClassMethod` for `presentSystemModalTouchBar:placement:systemTrayItemIdentifier:` / `minimizeSystemModalTouchBar:`), no bridging header; placement 1 hides the Control Strip. One custom item holds a 1004 pt `BarView` (equal-width buttons, fills the bar on a 13" MBP). Touch Bar detected by the `dispdfr` IORegistry node (Apple silicon) or model name (Intel). Re-presented on app activation and wake; minimized while a dialog is open. `screencapture -b` captures the Touch Bar for checks.
- **Touch Bar icons**: SF Symbols with the colors of the user's MTMR PNGs (sun #FFDB00, keyboard #4AD1E6, jiggler #0099FF, mic #FF5D49, screenshot #CC77F4, lock #7176EB, music #08DA73, weather #75DAD8, CPU/volume #FFAE02). Jiggler and mic show state by symbol, not only color (R-19).
- **Music control** (2026-11-13): Spotify and Apple Music get Apple Events (`playpause`, `next track`, `previous track`) so the exact player is driven; "any app" posts media keys (needs Accessibility). Taps counted in a 0.35 s window as in Hammerspoon. Block Apple Music = `terminate` on `didLaunchApplication` (as noTunes), `forceTerminate` if still running 2 s later, skipped while Apple Music is the chosen player.
- **CPU temperature in Swift** (2026-11-13): AppleSMC read with an explicit 80-byte `SMCKeyData` buffer (C offsets written out; no bridging header). Keys found once (TCMb or core keys scan) and cached. The Touch Bar reads every 10 s (30 s until 2026-11-13) only while the button exists and the screens are awake; the menu reads once when it opens.
- **Weather** (2026-11-13): CoreLocation with `kCLLocationAccuracyReduced` (needs the `personal-information.location` entitlement under hardened runtime), coordinates rounded to 0.1° (~11 km) before leaving the Mac; ephemeral URLSession; every 30 min, retry in 2 min on failure, timer and request cancelled on sleep, refresh 10 s after wake.

- **Footprint with the Touch Bar** (2026-11-13): ~20 MB with everything on, ~12 MB with the Touch Bar off (the Touch Bar's views and DFR cost ~7 MB; weather ~1 MB). Idle CPU ~0.1 %. Weather also pauses while the screens sleep.
- **Player = bundle id** (2026-11-13): `music.player` stores the chosen app's bundle id (or `mediaKeys`); old values `spotify`/`appleMusic` are migrated on read. Known players (Spotify, Apple Music, iTunes, YouTube Music desktop `com.github.th-ch.youtube-music`, Amazon Music `com.amazon.music`) are listed only when installed; "Choose another app…" (NSOpenPanel) covers the rest, e.g. Chrome web apps. Default: first installed known player. Only Spotify/Music/iTunes support Apple Events; the rest get media keys after opening, which reach the app macOS considers "now playing" (known limit).

- **Icons** (2026-11-13): one knife glyph for everything, generated by `scripts/make-icons.py` (edit its parameters, not the SVGs). Menu bar / Touch Bar tray: template SVG `MenuBarIcon` in `Assets.xcassets` (thick handle, 1.5 pt SVG-mask gap, one pivot hole; legible at 18 pt). App icon: Icon Composer `.icon` (`ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`), the glyph in white glass (translucency 0.3) at 640/1024 on a system-blue automatic gradient. `xcrun actool X.icon --compile out --app-icon X --platform macosx --minimum-deployment-target 26.0 --output-partial-info-plist p.plist` previews variants without building the app.
- **Settings window resizable** (2026-11-13): `.resizable`, hosting controllers with `sizingOptions = []` so switching tabs doesn't resize the window, frame autosaved as `PenknifeSettings`; Forms scroll by themselves.
- **Jiggler key** (2026-11-13): `jiggler.key` (Caps Lock ×2 default, Shift, Control, Option, F18, none); only keys that type nothing are offered. F15 discarded: on Apple keyboards F14/F15 change brightness.
- **Clipboard history** (2026-11-13): no pasteboard change notification exists, so a 0.5 s timer (0.25 s tolerance) compares `changeCount`; stopped while screens sleep and when the module is off. Idle cost measured at baseline (~19 MB footprint, ~0.15 % CPU). Only the data that will be kept is read; big data is fingerprinted by size + first/last 64 KB; memory in use is a running total.
- **Clipboard privacy**: skips nspasteboard.org concealed/transient/auto-generated markers and 1Password's own, and anything copied from Keychain Access, Passwords and common password managers (source from `org.nspasteboard.source`, else the front app). Pinned items: binary plist in Application Support/Penknife, folder 0700, file written under `umask(077)` (atomic temp files follow the umask); on load only file URLs are accepted.
- **Clipboard panel**: borderless non-activating `NSPanel` that can become key, so the app you were in stays frontmost. ⌘V is posted only when that same app is frontmost again and our panel is closed (retries up to ~0.35 s, else it only copies). Glass (`NSGlassEffectView`), opaque with border under Reduce Transparency / Increase Contrast. Keys handled in `sendEvent` so the search field keeps focus; VoiceOver gets announcements (selection, result count, pin, delete). Panel shortcuts (⌘1–9, ⌘P, ⌘⌫) are fixed on purpose; only the opening shortcut is customizable. Hover selection ignored for 0.4 s after a keyboard move.
- **Agents can't send keystrokes or capture the screen** (2026-11-13): `osascript` keystrokes and `screencapture` fail from Claude's shell (no Accessibility / Screen Recording). Panel UI checks fall to the user.
- **Screenshot editor** (2026-11-13): ScreenCaptureKit (`SCScreenshotManager`, full display resolution, no pointer, Penknife's windows excluded) — needs Screen Recording; first press shows the system prompt, later presses open System Settings. Frozen mode grabs every display at the shortcut; live mode grabs the display when the selection is made. One borderless panel per screen at `.screenSaver` level; the frozen image is the container layer's contents (GPU), the canvas draws only dim, selection, marks and handles. Penknife is activated during the session so pointer shapes work, and the previous app is reactivated on close. Window mode uses `CGWindowListCopyWindowInfo` bounds (layer 0, not ours) and crops the frozen image, so overlapping windows show as on screen. Marks are stored in screen points and drawn by the same code on screen and into the output bitmap. Pixelate uses `CIPixellate` with 14 pt blocks, made once per mark. Copy writes PNG only (half the pasteboard memory); the copy enters Penknife's clipboard history like any image (on purpose); Save writes `Screenshot yyyy-MM-dd at HH.mm.ss.png` (localized) to the chosen folder, else the system screenshot folder, else Desktop. Everything is released when the session closes.
- **Screenshot reviews** (2026-11-13, security/performance/accessibility): PNG only on the pasteboard; only the changed area is redrawn while dragging (selection + label, the mark being drawn); pen points appended in place. Keyboard: Return = whole screen (or the highlighted window), Space + arrows go through windows, arrows move and ⌥ arrows resize the selection, T then Return starts text; VoiceOver hears tool, color, undo/redo, size. Toolbar opaque under Reduce Transparency / Increase Contrast. Known limits: arrows, rectangles, pen, highlighter and pixelate need a pointer (no keyboard drawing); the toolbar isn't reached with Tab, its every button has a key instead.
- **Screenshot round 2** (2026-11-13, user feedback): blur replaces pixelate (`CIGaussianBlur`, radius 9 pt; the selection's background is blurred once when the blur tool starts and each mark crops it, so the drag shows real pixels). 8 colors with red and purple, 4 sizes for lines and text, ellipse tool. ⌘Z failed after typing text because the app's Edit ▸ Undo (enabled by the text view's undo actions) took ⌘Z before the window: the capture window now handles ⌘ keys in `performKeyEquivalent`. Holding Space flickered (key repeat toggled window mode): repeats of Space/Return/Esc are ignored. Window mode now captures the window alone with ScreenCaptureKit `desktopIndependentWindow` (rounded transparent corners, no shadow), or the desktop (windows with layer < 0: wallpaper and icons) when the pointer is over no window; such a selection can't be moved or resized.
- **Screenshot without activating Penknife** (2026-11-13): activating it made the front app inactive, so captured windows had grey title bar buttons. The overlay is a non-activating panel that still becomes key (keys and text work, as in the clipboard panel). Scroll wheel changes the size: physical direction (natural scrolling undone via `isDirectionInvertedFromDevice`), trackpads step every 24 pt.
- **Window focus before capture** (2026-11-13, user's idea): a window without focus is drawn inactive (grey title bar buttons) and SCK captures it that way; pre-capturing the front window and painting the buttons via Accessibility were tried and dropped. Now choosing a window focuses it behind the frozen overlay (AX raise + main, then app activate, ~180 ms to redraw), captures it, and the previous app is reactivated when the screenshot closes.
- **Images pastable in Finder** (2026-11-13): `Core/PastableImage.swift` puts one pasteboard item with PNG data + a file URL to a PNG in Caches/<bundle id>/Pastable/<uuid>/ (folders 0700, file 0600; oldest removed when the user's space limit is exceeded, checked on each write). Finder pastes the file, other apps the image (CleanShot does the same). The clipboard history keeps such an item as an image, not as a file reference.
- **Alerts (R-20, 2026-11-13)**: `HUD.show(title, detail:, symbol:, kind:, category:)`. `NSGlassEffectView` capsule (44 pt, 56 pt with a detail line, max 360 pt wide, truncates) at the top right of the screen with the pointer, 12 pt under the menu bar. The panel exists only while shown (`generation` guards a late fade-out); a new alert during the fade takes over in place. VoiceOver announcement is posted even when the type is hidden (`alerts.<category>`). Reduce Motion: no slide, no fade-out; Reduce Transparency: solid; Increase Contrast: solid + `labelColor` outline.
- **Menu bar dots (R-20)**: the status item image is drawn (not template) in `labelColor` with a fixed 6 pt dot column; `squareLength` without dots, `variableLength` with them. Redrawn only on a real state change (cached tuple). Inputs: observation tracking on `jiggler.isActive` and `manager.enabled`, a `MicrophoneWatcher` (CoreAudio listeners on the default input and its mute/volume, active only while the mic dot is shown), and the `menuBar.statusDots` key (other defaults writes are ignored). No input device = no mic dot. `MicrophoneWatcher` is shared code with the Touch Bar (each keeps its own instance; tiny cost).
- **Jiggler interval (R-24)**: `jiggler.interval`, values outside the list fall back to 10 s; changing it reschedules at once.
- **Measured after R-20** (2026-11-13): ~21 MB footprint, ~0.17 % idle CPU (one sample, within noise of the baseline).
- **Live design demos** (2026-11-13): glass alerts and menu bar dots were chosen from small compiled Swift scripts in the session scratchpad that show the real panels / status items on screen (offscreen renders don't show Liquid Glass). The user runs them with `! <path>`. `cursorarrow.motionlines.slash` doesn't exist; the jiggler "off" symbol is `cursorarrow`.
- **Touch Bar state icons (R-25, 2026-11-13)**: change notifications, no polling: brightness `DisplayServicesRegisterForBrightnessChangeNotifications` (private, observer pointer comes back in the callback), keyboard light `KeyboardBrightnessClient registerNotificationForKeys:["KeyboardBacklightBrightness"] keyboardID:block:` (unregister: `unregisterKeyboardNotificationBlock`), volume CoreAudio listeners (default output, volume, mute), playback from `com.spotify.client.PlaybackStateChanged` / `com.apple.Music.playerInfo` distributed notifications ("Player State"). Level notifications are coalesced (0.1 s) and ignored while screens sleep (re-read on wake): CoreAudio reads on the main thread cost ~tens of ms in bursts. `BarButton.show` redraws only when symbol/text/drawing changes; a label-only change just updates VoiceOver. Battery icon is drawn (`BatteryIcon`), SF Symbols only have quarter steps and a single bolt variant. Color mode raw values kept (0 multicolor, 1 monochrome, 2 rainbow); monochrome color stored as "RRGGBB" in `touchBar.monochromeColor`.
- **No haptics on the Touch Bar**: it has no actuator; `NSHapticFeedbackManager` only reaches the Force Touch trackpad under a finger. Tap feedback is a sound (`TapSound`, `touchBar.tapSound`).
- **Manual vs automatic Apple Music launch (R-6, 2026-11-13)**: decided at `willLaunchApplication` with `CGEventSource.secondsSinceLastEventType` (no permission needed) for `leftMouseDown`/`keyDown`, plus CoreAudio listeners on the default output device and device list (headphones). Media keys can't be used as a signal: `systemDefined` events also come with mouse clicks. Headphone clicks reach rcd without any HID event, so they read as "no input" → blocked. Verified: `open -a Music` from a shell (no input) is closed. Blocked launches are force-quit at once at `willLaunch` (a polite `terminate()` let the window appear).
- **Now Playing bridge** (2026-11-13): `NowPlayingBridge` (MusicModule.swift, owned by Block Apple Music) registers MPRemoteCommandCenter targets + paused MPNowPlayingInfo, no audio engine (the "silencio" variant wasn't needed). Only for Apple Events players: media keys posted to "any app" would route back to Penknife (loop). Headphone commands never open a closed player. Re-evaluated on `UserDefaults.didChangeNotification`. Importing MediaPlayer made a static in a Sendable closure need `nonisolated`.
- **Slicing game (R-23)** (2026-11-14): `SliceGameView` draws with CoreGraphics in `draw(_:)` from a 60 Hz `Timer`, which exists only while a game is open. It is stopped by `finish()` from the X, 6 s after game over, minimize, screens sleep, `com.apple.screenIsLocked`, module stop, or the view leaving its window. After game over, once nothing moves, the timer becomes a single one-shot wake-up. Colors, gradients, symbol images and texts are cached, and each tick only redraws the play field. Measured over ~1.5 min of real play: ~18 % CPU on average (peaks ~35 %), footprint 23→24 MB, back to 0 % / 23 MB at exit. Lowered (2026-11-14) by moving the play field to Core Animation layers: fruits, halves and bombs are CGImage sprites drawn once per style with the old CoreGraphics code (bitmap shadows need blur × backing scale, since they are in pixels), cached by kind, radius (half-point steps, so few sprites) and part. Layers come from pools, every update runs in a CATransaction with actions disabled, trail segments are CAShapeLayers whose glow uses an explicit `shadowPath` (no offscreen pass), and idle ticks with an empty field skip the commit. `draw(_:)` only paints the controls. Measured in real play: ~4.3 % average (peak 8 %), back to 0 % at exit. `finish()` drops the layers and sprites. The 3 s hold on the jiggler uses an `NSPressGestureRecognizer` plus a release guard, the same pattern as the time button.
- **Speed test (R-10)** (2026-11-14): `/usr/bin/networkQuality -c` run from a `DispatchQueue.global` block behind a continuation. Its output is read to EOF (it can exceed a pipe's buffer). The pid sits in an `OSAllocatedUnfairLock` so the tool can be killed on module stop or app quit; -1 means "cancelled while starting". Keys: `dl_throughput`/`ul_throughput` (bits/s), `base_rtt` (ms), `responsiveness` (RPM). Exit status 0 is not trusted: an error run still exits 0 with only `error_code` in the JSON. Rating bands come from the IETF responsiveness draft (Low < 300 ≤ Medium < 1000 ≤ High), because Apple doesn't publish its own. Capping with `-M` underestimates badly, so the test runs in full (20–45 s here). Touch Bar: needle-symbol sweep at 0.6 s (one redraw per step) only while testing.
- **Touch Bar layout (R-26)** (2026-11-14): `BarItem` (BarLayout.swift) holds each button's title, Settings symbol, color and owning module. Order and hidden buttons are string arrays in `touchBar.order` / `touchBar.hidden`; unknown names are dropped, new buttons are appended, and if nothing would show, the time stays. The module rebuilds only when the visible list changes (checked on each `UserDefaults.didChangeNotification`). Writes from another process (`defaults write`) don't reach the running app; that's fine, because only the Settings sheet writes them. Hidden buttons have no timers, since `updateTemperature` and `updateClock` stop when their button is missing. The reorder uses a custom `DragGesture`, because SwiftUI `List.onMove` didn't drag for the user in the demo.
- **Modules sidebar** (2026-11-14): `NavigationSplitView` inside the toolbar tab (`.toolbar(removing: .sidebarToggle)`), with System Settings-style tiles (white symbol on a per-module tint, gray when off). The selection is saved in `settings.selectedModule`. The window minimum is 680×420, and narrower saved frames are enlarged. Discarded: a compact list with an options sheet per module (the designer's pick) and more toolbar tabs. Drag reorder in R-26 measures in a named coordinate space of the list: in the row's own space the reference moved with the row, so a slow drag jittered at half a row.
- **Single sidebar Settings** (2026-11-14): `SettingsView` (Settings/SettingsView.swift) is a `NavigationSplitView` hosted directly in the window (`.fullSizeContentView`, no `NSTabViewController`). The page is saved as a string in `settings.selectedPage` ("general", "module.<id>", …). The window title comes from `.navigationTitle`. Tiles are 18 pt in the sidebar and 24 pt in the detail header; General and About are graphite (not gray), so they don't look like modules that are off. The extra gap between sidebar groups is an empty 6 pt section header. Module shortcut recorders live in both the module page and the Shortcuts page, and stay in sync through the same `KeyboardShortcuts` names.
- **Versions** (2026-11-14): `MARKETING_VERSION` holds the version (1.0 = phases 1–4 done); the build number is the git commit count, passed by `scripts/install.sh` as `CURRENT_PROJECT_VERSION`, so nothing is edited per build. About shows "1.0 (N)". Each version: entry in `CHANGELOG.md` + git tag `vX.Y`. Updates stay manual (reinstall with the script) until published; then Sparkle (R-17).
- **Settings opens focused** (2026-11-14): `NSApp.activate()` (cooperative) can be refused for a menu bar app, so Settings opened inactive and the sidebar jumped ~10 pt on the first click; `show()` uses `activate(ignoringOtherApps: true)`. Sidebar section headers can't be shorter than ~19 pt (`defaultMinListHeaderHeight` is ignored) and spacer rows are at least 24 pt, so the only clean group gaps are ~13 pt (no header) or ~32 pt.
- **License** (2026-11-14): MIT (`LICENSE`), `THIRD_PARTY_LICENSES.md` (KeyboardShortcuts, Open-Meteo; add Sparkle and its bundled externals when it lands), README with install, permissions, privacy, private APIs and a not-affiliated line. Legal review: no third-party code copied. Name "Penknife": low risk (no Mac app with that name, about 15 small unrelated GitHub repos, no trademark found by web search; check tmsearch.uspto.gov and EUIPO eSearch by hand before any paid launch).

- **Mic state bug** (2026-11-16): `isMuted` read the device's mute property even when it wasn't settable, while `toggle` muted with volume 0, so every press muted again on such devices. Read the same control that is set.
- **Hey Siri vs the mic mute** (2026-11-16): root cause, measured every 100 ms with Penknife closed: with "Listen for Hey Siri" on, any sound that starts the speakers makes corespeechd save the built-in mic's mute, clear it for ~1 s, then RESTORE the saved value, overwriting any change made in that second. Penknife's Touch Bar click played on touch-down, so the tap's own toggle landed inside that second and Siri undid it ("it mutes by itself"); F5 has no sound. Fix: Touch Bar buttons make no sound (click removed; the game keeps its own). A guard that re-muted after Siri was tried and removed (a patch that fought Siri; Siri restores by itself). Known limit: while muted, a notification sound leaves the mic open ~1 s. Input volume 0 is not a mute (−12 dB). The Touch Bar, the dot and toggles read the real device state. Logi Options+ also had an MX Keys key on MUTE_MICROPHONE (its own menu bar mic icon); the user remapped it to F5.
- **Siri and the mic icon** (2026-11-16): measured: Siri (`com.apple.CoreSpeech` in CoreAudio's process list) records even with the mic muted, and clears the mute while it listens, restoring it after. macOS sends NO notification when Siri starts or stops (2-minute test: 3 Siri sessions, zero events from devices, processes, workspace or distributed notifications; only the speakers when Siri answers). So no Siri badge (it would need polling: 0.03 % CPU at 0.5 s, rejected as invasive). The icon follows the device mute by subscription, which is truthful because Siri clears the mute itself; a press while Siri listens does nothing (one read at press time).

- **Meeting detection fix** (2026-11-16): measured in a live Meet call: (a) CoreSpeech (Siri) records alongside ANY app using the mic, for the whole call, so the old "Siri is listening" guard swallowed every press; now Siri counts only when it is the only process recording. (b) Browsers record from helpers whose bundle ID does not name the app (Chrome Dev → `com.google.Chrome.helper`, Safari → `com.apple.WebKit.GPU`, shared with Mail/Teams); each CoreAudio process is mapped to its responsible app with `responsibility_get_pid_responsible_for_pid` (private libsystem, via dlsym; fallback = the process itself) and matched by pid. (c) Browser meetings are told by the focused window title (Accessibility), not AppleScript URLs, so Chrome, Chrome Dev, Opera, Safari and Firefox all work and no Automation prompt appears. Titles are never logged. (d) Teams' local WebSocket API (port 8124, "Manage API") was retired by Microsoft on 2026-06-30 (MC1266901) and is closed here, so a meeting app's mute state can't be read; "Also mute the Mac's microphone" is now ON by default so the icon matches the call.

# Screenshot — requirements (current behavior)

Source of truth for what the Screenshot module (capture, annotate, copy, save) must do TODAY (Penknife 1.11; main at 88ffca7). The history behind each rule (who asked, when, what was tried) stays in `docs/REQUIREMENTS.md` (R-8, R-32, R-33 and the R-29 lines about the screenshot; R-12, R-15, R-19, R-20 for settings, keyboard and alerts) and `docs/DECISIONS.md`; where they disagree with this file, this file wins. Written 2026-11-19 from the code at 88ffca7 and those docs: third module of "complete requirements per module + tests that validate them" (user, 2026-11-17), after the microphone and the Touch Bar. Parts SHARED with screen recording are written here once and the recording rules will point to them: the overlay and its hint (§B, §C), the tools, their order, colors and sizes (§D, §E), mark editing R-32 (§F) and the Record entry from the capture overlay (§J). The recording itself (writer, GIF, end window, recording toolbar, draw shortcut) belongs to the REC rules (to be written). The Touch Bar's screenshot button is TB-22.

**How to use it.** Before changing anything that touches the screenshot overlay, its tools, the marks, Copy/Save or their settings, read the rules of the parts you change (and the REC rules once they exist: recording reuses §B–§F). After the change, run `scripts/test.sh` and check EVERY affected rule by its Verify line, not only the new behavior. A new or changed wish → change the rule here, and keep the story in REQUIREMENTS.md.

Code paths are relative to `Penknife/`: `SM` = Screenshot/ScreenshotModule.swift (ScreenshotMode, ScreenshotModule, ScreenGrabber, WindowFocus), `CS` = Screenshot/CaptureSession.swift (CaptureSession, CaptureWindow, CaptureTarget, CaptureCanvas), `CT` = Screenshot/CaptureToolbar.swift (CaptureEditorState, CaptureToolbar, MarkToolButtons, MarkStyleButtons, CaptureHint), `AN` = Screenshot/Annotation.swift (CaptureTool, CapturePalette, CaptureSize, Erasure, Annotation), `ME` = Screenshot/MarkEditing.swift, `PI` = Core/PastableImage.swift, `SC` = Core/Shortcuts.swift, `HUD` = Core/HUD.swift (AlertCategory), `MGR` = Core/ModuleManager.swift, `MOD` = Core/Module.swift, `SMN` = App/StatusMenu.swift, `MMN` = App/MainMenu.swift, `SV` = Settings/SettingsView.swift (ModuleDetail, ScreenshotOptions), `ST` = Settings/ShortcutsTab.swift. "D: <title>" = the DECISIONS.md bullet with that bold title.
Verify kinds: **auto** (unit test as the code is today) · **auto after refactor** (seam named; see §4) · **manual** (the user's normal action only) · **log** (none: the screenshot code logs nothing).
Count (2026-11-19, step B: as-is tests + S1 + S2 + S3, B-8 B-9 B-10 fixed): 59 rules = 36 auto · 10 auto after refactor · 0 log · 13 manual.
**Tests:** `PenknifeTests/ScreenshotRulesTests.swift` (24 tests, 2026-11-19), run with `scripts/test.sh`, each named after its rule ("SS-27 …"). Settings are read from `MemoryDefaults` (a `UserDefaults` subclass that answers from a dictionary and records an issue on any write), so no test value ever reaches disk. Never run a Screenshot action, `ScreenshotModule.begin`, `CaptureSession.show()` or `requestPermission` from a test: they open a real overlay over the user's screens or the Screen Recording prompt. Never call `PastableImage.copy`/`copyFile`/`makeRoom`/`removeAll` or touch `NSPasteboard.general` before S6: they write the user's clipboard and Caches folder.

## 1. Rules

### A. Module, triggers, permission

- **SS-01** "Screenshot" is one module (Settings › Modules, on by default, `module.screenshot.enabled`, purple tile `camera.viewfinder`; summary "Select an area or, with Space, a window. Mark it with arrows, text, highlighter, rectangles, circles, pen or blur, then copy or save it. Or record it as a video or GIF, drawing while you record. Nothing is uploaded." / "Selecciona un área o, con Espacio, una ventana. …"). It has two actions, in this order: "Screenshot" / "Captura de pantalla" (`camera.viewfinder`, shortcut `screenshot`, default F1) and "Record Screen" / "Grabar pantalla" (`record.circle`, shortcut `recordScreen`, default ⌃⌥R). Both are items of Penknife's menu (with their shortcut shown) and recorders in Settings › Shortcuts and on the module page, followed there by "Draw While Recording" / "Dibujar mientras grabas" (`recordingDraw`, default ⌃⌥D; registered only while recording: REC rules).

- **SS-02** Triggers: the shortcut (on key release; a bare F1 also gets its Fn twin, TB-58), the menu item (run after the menu has closed, so the menu is never in the image) and the Touch Bar button (TB-22). The Record Screen shortcut stops a running recording, switches an open overlay to record mode (SS-51), else opens the overlay in record mode (SS-52).
  Source: R-3; R-29 (11-17) "pressing it again stops"; D: One press = one action · Code: SM:begin (guards), toggleRecording; SMN:runAction; MGR:runHotKey · Verify: **auto after refactor** (S6) — a module with a fake environment: second press while open / starting / recording → no second session; manual — press F1 twice: one overlay.
- **SS-03** Module off: both shortcuts are unregistered (F1 reaches the front app), both menu items and the Touch Bar button go (TB-08), an open overlay is cancelled and a running recording is cancelled. On: `start` does nothing; no observer, timer or listener exists until a press.
  Source: R-15 "A module that is off uses no CPU/RAM" · Code: SM:start, stop; MGR:setEnabled, setShortcuts · Verify: **auto after refactor** (S6) — start/stop with a fake environment: stop cancels the open session and the recording, start creates nothing; manual — turn Screenshot off, press F1: nothing in Penknife.
- **SS-04** Screen Recording permission is checked at every press (`CGPreflightScreenCaptureAccess`). Not granted, first time ever (`screenshot.askedPermission` unset): the key is set and macOS's own prompt is shown (`CGRequestScreenCaptureAccess`), nothing else. - **SS-05** Capture failures: the frozen grab (SS-07) fails → HUD "Couldn't take the screenshot" / "No se pudo hacer la captura" (`exclamationmark.triangle.fill`, error = yellow, Screenshots type) and no overlay. - **SS-06** Nothing is uploaded: the screenshot code makes no network call; images go only to the clipboard, Penknife's caches (SS-48) and the save folder.

## 2. Open decisions, questions and known bugs

Questions for the user (asked 2026-11-19; recommendation in brackets):
- **O-12 No visible confirmation after Copy or Save.** Only VoiceOver hears "Screenshot copied" / "Screenshot saved" (SS-46, SS-48); the overlay just closes. Lightshot also shows nothing; macOS shows a thumbnail. The Screenshots alert type exists, but only errors use it. [Keep as is (fast, nothing to dismiss). If wanted: a short "Copied" / "Saved to <folder>" alert under the Screenshots type, designed with `ux-ui-designer`.]
- **O-13 "Space for images to paste as files" is a Screenshot option, but not only for screenshots.** Clipboard History's pasted images and the recording's Copy use the same space (SS-47), yet the row lives on the Screenshot page and is dimmed while Screenshot is off: a user without the Screenshot module can't change or empty it. [Show the same row (same key) on the Clipboard History page too, or move it to General.]
- **O-14 Penknife's own windows never appear in a screenshot.** Every grab leaves out all of Penknife's windows (SS-08), and window mode skips them: Settings, the clipboard panel, the recording end window and Penknife's menu bar icon and readings vanish from the image (what is behind them shows). Leaving out the overlay itself is needed only in live mode (in frozen mode it isn't on screen yet), and the HUD is the only other window that should never show. [Leave out only the overlay panels and the HUD; ask before building, since the web captures workflow relies on capturing Settings by other means.]
- **O-15 Drawing without a mouse (R-19 IMPERATIVE "EVERYTHING usable without a mouse … screenshot editor").** The selection, text, colors, sizes, undo, copy and save work by keyboard, but arrow, line, rectangle, circle and blur can only be drawn with a pointer (a known limit since 2026-11-13, SS-44). Since R-32, a selected mark can be moved and resized with the arrows. [A tool key then Return drops a mark of a default size in the middle of the selection, selected, so the arrows and ⌥ arrows place it; pen, highlighter and eraser stay pointer-only. `accessibility-reviewer` + `ux-ui-designer` first.]
- **O-16 A click inside a blur or a text selects it.** For those two the whole box counts as "on the mark" (SS-35), so an arrow can't start inside a blurred area or a text's box with the Arrow tool on: the click selects the blur/text instead. [Keep (Preview's Markup does the same); revisit only if the user trips on it.]

Not measured (check live; nothing to decide yet):
- Whether VoiceOver still speaks "Screenshot copied" / "Screenshot saved": the announcement is posted on the overlay window right before it closes.
- A display connected, disconnected or rearranged while the overlay is open: nothing listens for screen changes; the panels keep their old frames.
- A display that ScreenCaptureKit doesn't list (Sidecar, AirPlay): one missing display makes the whole frozen grab fail (SS-05), so no screenshot on any screen.
- macOS's periodic Screen Recording re-confirmation for ScreenCaptureKit apps, and the Mac locking or sleeping while the overlay is open (screen-saver level).

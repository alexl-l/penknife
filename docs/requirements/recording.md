# Screen recording — requirements (current behavior)

Source of truth for what screen recording (countdown, capture, drawing while recording, menu bar indicator, end window with trim, video, GIF and copy) must do TODAY (Penknife 1.11; main at b5d3ad2). The history behind each rule (who asked, when, what was tried) stays in `docs/REQUIREMENTS.md` (R-29, R-32 and R-33 for recording; R-11, R-15, R-19, R-20 for cost, keyboard and alerts) and `docs/DECISIONS.md` (R-29 screen recording and the entries after it); where they disagree with this file, this file wins. Written 2026-11-19 from the code at b5d3ad2 and those docs: fourth module of "complete requirements per module + tests that validate them" (user, 2026-11-17), after the microphone, the Touch Bar and the screenshot. Recording belongs to the Screenshot module (SS-01): the overlay and its hint, the tools, their order, colors and sizes, mark editing and the Record entry are written once in `screenshot.md` (§B–§F, §I) and are only pointed to here. The "For later" wishes in REQUIREMENTS.md (Esc while recording, toolbar during the countdown, auto-close of the end window, speeding up a recording) are NOT current behavior and are not rules here.

**How to use it.** Before changing anything that touches recording, read the rules of the parts you change, and the SS rules they point to (recording reuses the overlay, the tools and mark editing). After the change, run `scripts/test.sh` and check EVERY affected rule by its Verify line, not only the new behavior. A new or changed wish → change the rule here, and keep the story in REQUIREMENTS.md.

Code paths are relative to `Penknife/`: `RS` = Recording/RecordingSession.swift (RecordingRequest, RecordingSession), `RC` = Recording/RecordingCanvas.swift (OverlayPanel, FirstClickHostingView, StrokeCanvas, MarkView, DrawingInputView, BlurOverlay, RegionFrameView, CountdownView, CountdownCapsule), `RT` = Recording/RecordingToolbar.swift, `RE` = Recording/RecordingEndWindow.swift (RecordingResult, RecordingEndWindow, EndPanel, RecordingEndView, TrimBar), `RX` = Recording/RecordingExport.swift, `RW` = Recording/RecordingWriter.swift (RecordingLog, RecordingError, RecordingWriter), `SR` = Recording/ScreenRecorder.swift, `RST` = Recording/RecordingState.swift (RecordingPrefs, RecordingState, RecordingCommand, RecordingIndicator), `GIF` = Recording/GIFEncoder.swift, `FB` = Recording/FrameBlur.swift, `CS` = Screenshot/CaptureSession.swift, `CT` = Screenshot/CaptureToolbar.swift, `CK` = Screenshot/CaptureKeys.swift, `CG` = Screenshot/CaptureGeometry.swift, `SM` = Screenshot/ScreenshotModule.swift (ScreenshotModule, WindowFocus), `ME` = Screenshot/MarkEditing.swift, `PI` = Core/PastableImage.swift, `SC` = Core/Shortcuts.swift, `HUD` = Core/HUD.swift, `SMN` = App/StatusMenu.swift, `MMN` = App/MainMenu.swift, `AD` = App/AppDelegate.swift, `SV` = Settings/SettingsView.swift, `ST` = Settings/ShortcutsTab.swift. ## 1. Rules

### A. Starting

- **REC-01** Ways in: the "Record Screen" / "Grabar pantalla" action (menu item and shortcut `recordScreen`, default ⌃⌥R; SS-01) opens the overlay straight in record mode (SS-52); from the screenshot editor the Record button, ⇧⌘R or the Record Screen shortcut start at once with the selection, else switch to record mode (SS-51). The Touch Bar has no record button (TB-22). The Record Screen shortcut while recording stops (REC-30), during the countdown cancels (REC-07), while the files are being finished does nothing. Once the end window is open the recording is over for the module: a new screenshot or recording can start, and several end windows can be open at once.
  Source: R-29 (11-17) "pressing it again stops"; R-33 · Code: SM:actions, toggleRecording, startRecording, begin; RS:stop · Verify: **auto after refactor** (S6) — a session with a fake environment: stop in countdown → cancelled, in recording → finishing, in finishing → nothing; manual — ⌃⌥R, drag, wait for the toolbar, ⌃⌥R: the end window opens.
- **REC-02** Screen Recording permission: the same check, first-time prompt and later HUD + System Settings as a screenshot (SS-04), at every Record Screen press that opens the overlay.
  Source: R-29; D: Screenshot editor · Code: SM:begin, requestPermission · Verify: covered by SS-04 (S6 of screenshot.md).
- **REC-03** What the overlay hands over: the screen, the region on it in points (its part on that screen, CG:recordRegion; at least 8 × 8 pt), "full screen" when the region is the whole screen, the chosen window (id and frame) when it was chosen as a window, the editor's marks (REC-26), the remembered microphone and Mac sound switches (REC-27) and the app that was in front. The overlay closes before anything else happens.
  Source: R-29 "an area, a window or the full screen"; R-33 · Code: CS:startRecording, record; RS:RecordingRequest · Verify: **auto** — `CaptureGeometry.recordRegion` (already tested, SS-51); manual — ⌃⌥R, Return: the whole screen is recorded with no edge line (REC-13).
- **REC-04** Before the countdown: if the microphone switch is on, its permission is checked (REC-28; the macOS prompt, if any, comes now); then a chosen window is brought to the front (raised through Accessibility when allowed, its app activated, 0.18 s to redraw), else the app that was in front is activated; then a private temp folder is made (`<tmp>/Penknife Recording <UUID>`, 0700). If the folder can't be made: HUD "Couldn't record the screen" (REC-07) and nothing else.
  Source: R-29 "Window = the window's area on screen, brought to the front first"; DECISIONS R-29 (temp files) · Code: RS:start; SM:WindowFocus.focus · Verify: **auto after refactor** (S6) — fake environment: mic on → permission asked before the countdown; window → focus called with its id; manual — Space, click a window behind another, ⌃⌥R path: it comes to the front before the 3-2-1.

### B. Countdown

- **REC-05** Look (R-33 variant A; O-32, user's pick A, 2026-11-19: "que la barra de herramientas no se esconda cuando se hace el conteo"): nothing is dimmed; a 1 pt accent line (90 %) around the region (its own panel, lets clicks through). The recording toolbar (REC-11) shows from the first second, in its place under the region, with "Recording in 3" / "Grabando en 3" (13 pt semibold, monospaced digits, numeric transition; a plain fade under Reduce Motion; VoiceOver "Recording in 3 seconds") in the time's place. During the countdown only Stop (as Cancel, help "Cancel (Esc)", VoiceOver "Cancel recording"), Microphone and Mac sound (REC-27, keys M and S; O-18) work; Pause, the Pointer and tools, color, size, the Drawings menu and Erase all are dimmed. The toolbar takes the keyboard until time 0 (Esc, M, S; other ⌘ keys stay there, B-13), then gives it back (REC-08). VoiceOver hears once "Recording in 3 seconds. M: microphone, S: Mac sound, Esc cancels." / "La grabación empieza en 3 segundos. M: micrófono, S: sonido del Mac, Esc para cancelar." Never in the file.
  Source: R-33 (11-17) countdown CHOSEN variant A · Code: RS:showCountdown; RC:CountdownView, CountdownCapsule · Verify: manual — ⌃⌥R, drag: a thin line around the area and "Recording in 3, 2, 1" at the top.
- **REC-06** Timing: 3 → 2 → 1, one step a second (0.05 s tolerance); the first switch touched (click, M or S) restarts it at 3, once per recording (O-18); the capture starts during the countdown; the recording's time 0 is the end of the countdown, or the moment the capture is ready if that is later; then the count becomes the time 0:00, the dimmed buttons wake up, Stop becomes Stop (REC-30) and the toolbar resizes to its recording width; the newest frame from before time 0 opens the movie, so it never starts black.
  Source: DECISIONS R-29 (t = 0 at the end of the countdown) · Code: RS:countdownTick, prepare, go; RW:begin, appendVideo (pendingFrame) · Verify: **auto after refactor** (S4) — timeline: begin at t → a frame from before is written at 0, earlier ones dropped; log — "Capture ready: …" appears before "Recording".
- **REC-07** Esc during the countdown (the toolbar holds the keyboard; M and S flip the switches, other ⌘ keys stay there), the toolbar's Stop (Cancel while counting, O-32) or the Record Screen shortcut cancels: everything closes, nothing is kept, no alert. Esc does nothing after time 0 (it never stops a recording; user 2026-11-19: "se puede oprimir por error"). A capture that can't start (display not found, ScreenCaptureKit error, writer error) or that macOS stops during the countdown → HUD "Couldn't record the screen" / "No se pudo grabar la pantalla" (`exclamationmark.triangle.fill`, error, Screenshots type) and everything closes. The menu bar shows no recording indicator yet (REC-31).
  Source: R-33 "Esc cancels at any point"; DECISIONS Reviews (no false error when cancelling during the countdown) · Code: RS:showCountdown (onKey), stop, cancel, fail, prepare (catch), captureStopped · Verify: **auto after refactor** (S6) — cancel → HUD sink empty, folder removed; failing start → one HUD; manual — ⌃⌥R, drag, Esc during "Recording in 2": nothing is left on screen.

### C. What is recorded

- **REC-08** The file: the chosen display, cropped to the region (area or window; full screen = no crop); size = region × the screen's backing scale, shrunk to fit the hardware H.264 encoder (at most 4096 px on the long side and 4096 × 2304 px in all), even numbers, at least 64 px a side. Up to 30 frames a second, a frame only when the screen changes. H.264 High, BT.709 colors, average bit rate 3 bits per pixel per second within 2–24 Mbit/s, a key frame every 2 s.
  Source: R-29 "each record exactly that region"; DECISIONS R-29 (capped for hardware H.264) · Code: RS:prepare, pixelSize; RW:init · Verify: **auto after refactor** (S2) — `pixelSize`: 1440 × 900 pt at 2× → 2880 × 1800; 3000 × 2000 pt at 2× → fits 4096 and 4096 × 2304, even; 10 × 10 pt → 64 × 64; log — "Capture ready: 2880×1800 …".
- **REC-09** In the file: the screen in the region, the pointer, and the drawings (REC-20). Never in the file: any other Penknife window (toolbar, region edge, countdown, HUD, blur glass, selection handles, the end window, Penknife's menus). Other apps' windows that cover the region are recorded. A window recording is the window's area when it was chosen: moving the window doesn't move the region.
  Source: R-29 acceptance "Penknife's toolbar and panels never appear in the file"; R-29 "pointer shown in the recording" · Code: RS:prepare (filter = display excluding Penknife except the drawing window; `showsCursor`) · Verify: log — "drawings included: true"; manual — record an area with the toolbar inside it (REC-12), play the file: no toolbar, the pointer shows.
- **REC-10** After the countdown the keyboard goes back: the chosen window's app (else the app that was in front) is activated, so typing reaches it. Penknife is never the active app while recording.
  Source: R-29 acceptance "With drawing off, clicks and typing reach the apps underneath" · Code: RS:go · Verify: manual — ⌃⌥R, Return, type in the front app after the countdown: the text appears there.

## 4. Test plan (step B proposal)

Proposed 2026-11-19. Same method as the microphone, the Touch Bar and the screenshot: each seam is a pure rule the app keeps calling with exactly the same reads, tests pass plain values, each test is named after its rule and is seen to fail with its rule broken on purpose (one mutation run per step). No S-step changes behavior; B-13…B-16 are fixed only after the user's yes, each in its own commit, after the S-step that can guard it.

Warnings: the test host is Penknife.app: `UserDefaults.standard` is the user's real settings (`RecordingPrefs` setters write it: never call them; use `MemoryDefaults` as in ScreenshotRulesTests), and the temp folder is shared with the app, which deletes "Penknife Recording …" folders at launch and quit: tests use their own prefix.

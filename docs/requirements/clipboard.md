# Clipboard History — requirements (current behavior)

Source of truth for what Clipboard History (watching the clipboard, the history and pinned items, the panel, pasting, its settings) must do TODAY (main at c49286f). The history behind each rule stays in `docs/REQUIREMENTS.md` (R-7; R-11, R-15, R-19, R-20 for cost, keyboard, accessibility and alerts) and `docs/DECISIONS.md` (Clipboard history, Clipboard privacy, Clipboard panel, Images pastable in Finder); where they disagree with this file, this file wins. Written 2026-11-19 from the code at c49286f and those docs: fifth module of "complete requirements per module + tests that validate them" (user, 2026-11-17), after the microphone, the Touch Bar, the screenshot and the recording. The "Idea for later" in R-7 (select several items and paste them together) is NOT current behavior and is not a rule here.

**How to use it.** Before changing anything that touches the clipboard history, read the rules of the parts you change. After the change, run `scripts/test.sh` and check EVERY affected rule by its Verify line, not only the new behavior. A new or changed wish → change the rule here, and keep the story in REQUIREMENTS.md.

Code abbreviations: CM = `Clipboard/ClipboardModule.swift`, CS = `Clipboard/ClipboardStore.swift`, CP = `Clipboard/ClipboardPanel.swift`, SV = `Settings/SettingsView.swift` (ClipboardOptions), PI = `Core/PastableImage.swift`, MO = `Core/Module.swift`.

**Tests:** `PenknifeTests/ClipboardRulesTests.swift` (34 tests, 2026-11-19; S1–S5 done), run with `scripts/test.sh`, each named after its rule ("CB-14 …"). Stores are made with `ClipboardStore(folder:limit:)` on a temp folder; never `ClipboardStore()` (its `init` reads and its pin changes write the user's real `~/Library/Application Support/Penknife/Pinned.plist`). Never read or write `NSPasteboard.general` (use `NSPasteboard(name:)` with a unique name and `releaseGlobally()`), never make `ClipboardModule()` with its defaults (real store, `.general`); a test module is `ClipboardModule(store:pasteboard:frontApp:)` on a temp store and a private pasteboard, and calls `use` only with `paste: false` (with `true` it asks for Accessibility and posts ⌘V); a test that calls `start()` calls `stop()` before it returns, so the timer never fires, never open a `ClipboardPanel`, never write `UserDefaults.standard` (use `MemoryDefaults` as in ScreenshotRulesTests).

## 1. Rules

### A. The module

- **CB-01** Module "Clipboard History" / "Historial del portapapeles" (symbol `list.clipboard`, teal in Settings), on by default. Description: "Remembers what you copy (text, images and files) so you can search it and paste it again. Passwords are skipped. Only pinned items are kept after quitting." / "Recuerda lo que copias (texto, imágenes y archivos) para buscarlo y volver a pegarlo. Las contraseñas se ignoran. Al salir solo se conservan los elementos fijados."
  Source: R-7; D: Copy review · Code: MO:title, summary, symbol, defaultOn; SV:color · Verify: manual — Settings › Clipboard History: the switch is on and the text reads as above.
- **CB-02** One action, "Clipboard History", in the Penknife menu and as the shortcut `clipboardHistory` (default ⌃⌥V, customizable in Settings like every shortcut): it opens the panel; pressed while the panel is open, it closes it. Only the opening shortcut is customizable; the panel's own keys are fixed (CB-22).
  Source: R-7 "Shortcut customizable, default ⌃⌥V"; D: Clipboard panel · Code: CM:actions, showPanel; Shortcuts.swift:11 · Verify: manual — ⌃⌥V opens the panel, ⌃⌥V again closes it.
- **CB-03** Turning the module off stops watching, closes the panel and empties the history; pinned items stay on disk and come back when it is turned on. Turning it on starts from the clipboard as it is now: what was copied while off is not added.
  Source: R-7 "Turning the module off empties the history (pins stay)" · Code: CM:start, stop · Verify: **auto** (S3 done) — a store with history and pins, module stop → history empty, pins kept; manual — copy something, turn the module off and on, ⌃⌥V: only pinned items show.
- **CB-04** Lives in memory only: the history is gone when Penknife quits or the Mac restarts. Only pinned items are kept (CB-15).
  Source: R-7 "Lives in memory only" · Code: CS (no history file) · Verify: manual — copy a text, quit and open Penknife, ⌃⌥V: it isn't there.

### B. Watching the clipboard

- **CB-05** macOS sends no "clipboard changed" signal, so a 0.5 s timer (0.25 s tolerance, common run-loop modes) compares the clipboard's change count; nothing is read unless it changed. The timer runs only while the module is on and the screens are awake (stopped at "screens did sleep", started at "did wake"). Opening the panel checks once first, so a copy made a moment ago is already in the list.
  Source: D: Clipboard history; R-11 (minimum cost) · Code: CM:startTimer, check, start (sleep/wake observers), showPanel · Verify: log/measure — idle ~0.15 % CPU, ~19 MB (D, 2026-11-13; `measure-resources`); manual — ⌘C a word and ⌃⌥V at once: it is the first row.
- **CB-06** Passwords and temporary data are never stored: a copy carrying any of `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`, `com.agilebits.onepassword`, `com.agilebits.onepassword.ConcealedType`, `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping` is skipped; so is anything copied by Keychain Access, Passwords, 1Password (7 and 8), Bitwarden, KeePassXC, LastPass and Dashlane, marked or not. The source app is the one the copy names (`org.nspasteboard.source`), else the app in front when the change is seen.
  Source: R-7 "Skip concealed/transient items (passwords)"; D: Clipboard privacy · Code: CM:skipped, skippedApps, read · Verify: **auto** (S2 done) — a private pasteboard with a string + ConcealedType → nil; source `com.apple.Passwords` → nil; plain string → a text item; manual — copy a password in Passwords, ⌃⌥V: it isn't there.
- **CB-07** What kind a copy is, in this order: (1) file URLs → a files item (references to the originals, never copied), unless every URL is one of Penknife's own pastable images (PI:isOurs) and an image is offered too → that image (CB-08); (2) text when the copy has text and either no image or rich text too (Word and Pages offer a picture of the text: rich text means text) → a text item with the plain text and, if offered, the RTF and the HTML (web pages often offer HTML and no RTF; O-20); empty text is not stored; (3) PNG, else TIFF → an image item with those bytes as they are. Anything else (only HTML, a color, a URL that isn't a file…) is not stored. Only the data that will be kept is read.
  Source: R-7 "Stores text, images and files (files as references)"; D: Clipboard history ("Only the data that will be kept is read"); D: Images pastable in Finder; O-20 (user, 2026-11-19) · Code: CM:ClipboardReader.read · Verify: **auto** — "CB-07 what kind a copy is", "CB-07 CB-25 O-20 web formatting".
- **CB-08** A repeat moves up instead of being stored twice. Two copies are the same when their fingerprint matches: SHA-256 of the kind and of each part's size and content (text: its UTF-8; image: its bytes; files: each path), where a part bigger than 128 KB counts only its first and last 64 KB. Only copies of the same kind can match: a copied path is not the file it names (B-17). Saved pins get their fingerprint derived again at launch, so pins from older versions still match. A repeat of a pinned item only updates its date: it stays where it is and is not added to the history. A repeat of a history item takes the old one's place at the top.
  Source: D: Clipboard history ("big data is fingerprinted by size + first/last 64 KB") · Code: CS:ClipItem.fingerprint, contentKey, add · Verify: **auto** — "CB-08 a repeat moves up…", "B-17 a copied path and that same file are different copies", "B-17 a pin saved with the old fingerprint still matches".
- **CB-09** Penknife's own writes are not new copies: after choosing an item (CB-24) the change count is taken as seen, so the item only moves to the top (CB-13).
  Source: R-7 · Code: CM:use (lastChange) · Verify: manual — choose the third row, ⌃⌥V: it is first, and it is not listed twice.

### C. The history and its limit

- **CB-10** One item = text (plain + optional RTF), an image (bytes + type), or files (URLs); plus the source app's bundle id (for the icon), the date and pinned or not. Its weight against the limit = the text's UTF-8 bytes + the RTF + the HTML + the image bytes + the paths' UTF-8 bytes.
  Source: R-7 "Limit by memory used" · Code: CS:ClipItem, bytes · Verify: **auto** — `ClipItem(text: "abc", rtf: 10 bytes).bytes` = 13; files ["/a/b"] = 4.
- **CB-11** Limit by memory, not by days or count: "Memory for the history" / "Memoria para el historial" (`clipboard.limitMB`: 25, 50, 100, 250 or 500 MB; default and any unknown value 100 MB). Over the limit the oldest unpinned items go first, at every add and when the setting changes. A single copy bigger than the limit is not stored. Pinned items don't count.
  Source: R-7 "Default 100 MB (our choice), configurable … oldest unpinned items drop first" · Code: CS:limitKey, limits, limitBytes, add, trim; SV:Picker (.onChange → trim) · Verify: **auto** (S1 done) — limit 25 MB, add 10 + 10 + 10 MB → the first is gone, used 20 MB; a 30 MB item → not stored; stored 0 → 100 MB.
- **CB-12** Memory in use is a running total, shown in Settings as "In use: 12,3 MB" / "En uso: …" (memory byte style) and updated live.
  Source: D: Clipboard history ("memory in use is a running total") · Code: CS:usedBytes; SV:LabeledContent · Verify: **auto** (S1 done) — after adds, removes, pins, unpins and clear, `usedBytes` = the sum of the history's `bytes`.
- **CB-13** Order: History newest first; an item chosen from the history moves to the top with a new date (as a new copy would); a pinned item chosen stays in place.
  Source: R-7 · Code: CS:add, touch · Verify: **auto** (S1 done) — history [c, b, a], touch a → [a, c, b]; touch a pinned id → no change.
- **CB-14** Delete removes one item (history or pinned). "Clear History" removes every unpinned item and never a pinned one; it asks first, in the panel and in Settings: "Clear the clipboard history?" / "¿Borrar el historial del portapapeles?", "Pinned items are kept." / "Los elementos fijados se conservan.", Clear / Borrar (destructive), Cancel / Cancelar. With an empty history the button is dimmed and ⌘⇧⌫ does nothing.
  Source: R-7 "Manual clear: one item or the whole history"; R-7 IMPERATIVE "not by … 'clear history'" · Code: CS:remove, clearHistory; CP:confirmClear, footer; SV:confirmationDialog · Verify: **auto** (S1 done) — clear → history empty, pins unchanged, used 0; remove a pinned id → gone from pins and from the saved file.

### D. Pinned items

- **CB-15** PINNED ITEMS ARE NEVER DELETED, NOT BY QUIT, RESTART, THE LIMIT, "CLEAR HISTORY" OR TURNING THE MODULE OFF; ONLY WHEN THE USER DELETES ONE. Settings says so: "Pinned items are saved on this Mac and never deleted unless you remove them." / "Los elementos fijados se guardan en este Mac y nunca se borran salvo que los quites tú."
  Source: R-7 IMPERATIVE · Code: CS:trim (history only), clearHistory, savePins; CM:stop · Verify: **auto** (S1 done) — limit, clear and module stop leave the pins; manual — pin a text, quit and open Penknife, ⌃⌥V: it is under "Pinned". See B-18.
- **CB-16** Pin (⌘P, right-click, VoiceOver action) moves a history item to the bottom of "Pinned" (pins in the order they were pinned) and takes it out of the memory total; Unpin moves it to the top of the history, counts it again and trims the others: the unpinned item itself stays even if it alone is over the limit (O-21); like any item it leaves when newer copies need the room (the next copy, if it alone is over the limit). The selection follows the item; VoiceOver "Pinned" / "Fijado", "Unpinned" / "Sin fijar".
  Source: R-7 "pin the most used items" · Code: CS:togglePin; CP:togglePin · Verify: **auto** (S1 done) — pin b of [c, b, a] → pins [b], history [c, a], used drops by b; unpin → history [b, c, a].
- **CB-17** Saved on every pin, unpin and delete of a pin as a binary property list `~/Library/Application Support/Penknife/Pinned.plist`: folder 0700, file 0600, written atomically under `umask 077` so no temp file is ever readable by others; no pins = no file. Read once at launch, pin by pin (only the id and kind are required; any other field may be missing); only file URLs are accepted back. If any pin can't be read (a kind this version doesn't know, a damaged file), the file is first set aside untouched as "Pinned (unreadable).plist" (" 2", " 3"… if taken; copied when some pins were readable, moved when none were; made 0600; the same bytes are set aside only once, not at every launch), and if that fails no pin is saved in that run, so a file is never written over a pin it couldn't read (B-18). A save that fails is only logged.
  Source: R-7 "saved to disk (app's Application Support, owner-only permissions)"; D: Clipboard privacy · Code: CS:loadPins, SavedPin, ClipItem.init(from:), unreadablePinsFile, savePins · Verify: **auto** — "CB-17 pins file…", "B-18 an unreadable pins file is never written over".

### E. The panel

Built when opened and released when closed (no memory while hidden). Opaque window background under Reduce Transparency or Increase Contrast, plus a 1 pt label-color border under Increase Contrast. VoiceOver: the panel is "Clipboard History".

### F. Using an item

- **CB-25** Choosing an item puts it back on the clipboard: text = plain text, plus the RTF and the HTML when "Keep text formatting" / "Mantener el formato del texto" (`clipboard.keepFormatting`, on by default; "Fonts, bold and colors. ⇧↩ in the history does the opposite once.") is on, or off with ⇧Return; ⇧ inverts it only that time; an image = its bytes as copied, except when the app in front when the panel opened is Finder: then a PNG file in Penknife's pastable images (named "Image 2026-11-19 at 16.30.05" / "Imagen 2026-11-19 a las 16.30.05", SS-47's space and rules) plus the PNG, so Finder pastes a file into the open folder; files = the same file references. Then the item moves up (CB-13) and the panel closes.
  Source: R-7 "Text formatting configurable … ⇧Return in the panel does the opposite once"; R-7 "Images chosen … while Finder is in front are pasted as a PNG file into the open folder" · Code: CM:use, keepsFormatting; PI:copy, timestampName · Verify: **auto** (S5 done) — `ClipboardWriter.write(item, to: private pasteboard, keepsFormatting:, invert:, finder:)`: text with RTF, keep on → .rtf + .string; keep on + invert → only .string; image + Finder → PNG + a file URL in a temp folder; manual — copy bold text in TextEdit, paste it from the history in TextEdit: it stays bold; ⇧Return: plain.
- **CB-26** Pasting: with "Paste after choosing an item" / "Pegar al elegir un elemento" (`clipboard.paste`, on by default) Return, a click, ⌘1–9, Paste in the menu and VoiceOver's action also press ⌘V; ⌥Return and Copy only copy. ⌘V is pressed only in the app that was in front when the panel opened, once it is in front again and no Penknife window has the keyboard (first check after 0.05 s, then up to six more tries 0.05 s apart, bringing it to the front each time); if that app quit or never comes back, the item stays copied and nothing is pressed.
  Source: R-7 Settings "Paste after choosing an item (on; needs Accessibility, otherwise it only copies and says so)"; D: Clipboard panel ("⌘V is posted only when that same app is frontmost again and our panel is closed") · Code: CM:use (pasteWhenReady), pastes; EventPoster.key · Verify: manual — in TextEdit, ⌃⌥V, Return: the text is pasted where the cursor was.

  Source: R-7; R-20 (alert types) · Code: CM:use; Permissions.ensureAccessibility; HUD · Verify: manual (needs Accessibility removed; leave to qa-tester on a test Mac or skip).

### G. Settings, cost, privacy, language

- **CB-32** Files that no longer exist (moved, deleted, a disk unplugged) leave the list: each time the panel opens (never at other times), checked off the main thread (a network disk can take seconds) and applied when the answer comes, every files item in the history loses its missing files, and one with none left is deleted. A pinned files item is never deleted (CB-15): while all its files are missing it is hidden, and it shows again when they are back (a disk plugged in again).
  Source: O-22 (user, 2026-11-19: "se debe limpiar el elemento de la lista. ya no debe aparecer"); R-7 IMPERATIVE pins · Code: CS:fileURLs, missing, dropMissingFiles; CM:showPanel; CP:hide, ClipboardPanelModel.hidden · Verify: **auto** — "O-22 files that no longer exist leave the history; pins are only hidden"; manual — copy a file in Finder, move it to the Trash and empty it, ⌃⌥V: it isn't listed.
- **CB-28** The Clipboard History page in Settings, in this order: "Memory for the history" (CB-11), "Paste after choosing an item" (CB-26), "Keep text formatting" with its note (CB-25), "Open the history" (CB-19), then "In use: …" with the pins note (CB-12, CB-15) and "Clear History…" (CB-14). The page shows the options only while the module exists (always: it is built at launch).
  Source: R-7 Settings · Code: SV:ClipboardOptions · Verify: manual — Settings › Clipboard History shows those rows in that order.
- **CB-29** Cost: nothing but the 0.5 s change-count check runs while idle; no panel, thumbnails or icons exist while the panel is closed; the history is kept in memory as the bytes that were copied (no copies, no previews).
  Source: R-11; D: Clipboard history · Code: CM:startTimer; CP (caches live in the model) · Verify: measure — `measure-resources` with the panel closed: ~0.15 % CPU (baseline 2026-11-13).
- **CB-30** Nothing is uploaded: the module makes no network call; data goes only to memory, the clipboard, Pinned.plist and the pastable images folder (Finder pastes).
  Source: R-7; general privacy rule · Code: CM, CS, CP (no URLSession) · Verify: **auto** — a source check: no `URLSession`, `URLRequest` or `NWConnection` in `Penknife/Clipboard/` (catalog test, as REC-47).
- **CB-31** Every visible string has its Spanish translation (the ones quoted above); VoiceOver strings too.
  Source: general (Spanish always) · Code: Localizable.xcstrings · Verify: **auto** — catalog test: each CB string has an "es" value.

## 2. Open decisions, questions and known bugs

Questions for the user (asked 2026-11-19; recommendation in brackets):
- **DECIDED 2026-11-19 (user: "a mí me gusta sin formato pero esta opción debe ser configurable"): the HTML is kept too and follows "Keep text formatting" like the RTF (CB-07, CB-25); the switch stays.** **O-20 Formatting from web pages is lost.** Only RTF counts as formatting (CB-07, CB-25). Safari and Chrome put HTML on the clipboard (Chrome often no RTF), so text copied from a web page and pasted from the history arrives plain even with "Keep text formatting" on. [Keep HTML too when the copy has it, and write it back with the RTF; small change, needs a test with a private pasteboard.]
- **DECIDED 2026-11-19 (user: "Conservarlo y borrar solo los demás, sin aviso"): CB-16.** **O-21 Unpinning an item bigger than the memory limit deletes it.** Unpin puts the item at the top of the history and trims (CB-16): a 300 MB pinned image with a 100 MB limit is gone at once, together with the whole history. Rare. [Keep the item and drop the others only down to it; or refuse to unpin with a short alert. My pick: the first, no alert.]
- **DECIDED 2026-11-19 (user: "se debe limpiar el elemento de la lista. ya no debe aparecer"): CB-32; pinned ones are hidden, not deleted (CB-15).** **O-22 Files that no longer exist.** A files item keeps the paths; if the files were moved or deleted, pasting it does nothing in Finder and there is no sign in the list. [Leave as is; or dim the row and say "Not found" in its VoiceOver text. Needs `ux-ui-designer` with live variants if wanted.]

Not measured (check live; nothing to decide yet):
- Copies from apps that offer only HTML or only a URL type (CB-07: not stored): which common apps do this (Chrome "Copy link", Slack).
- Search speed with a big text item (a 20 MB log): the whole text is searched on every keystroke on the main thread.

- **FIXED 2026-11-19 (c3ca50b; pins read one by one, the file set aside untouched; test seen to fail first):** **B-18 An unreadable pins file is overwritten on the next pin, losing every pinned item (breaks CB-15, R-7 IMPERATIVE "PINNED ITEMS ARE NEVER DELETED").** `loadPins` gives up on any decoding error and starts with no pins (ClipboardStore.swift:162-171); the next pin, unpin or delete writes the new, short list over the file (:173-190).

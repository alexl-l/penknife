# Macros — requirements (current behavior)

Source of truth for what Macros (R-35) must do TODAY. The story behind each rule (the user's words, what was rejected) stays in `docs/REQUIREMENTS.md` (R-35); technical choices in `docs/DECISIONS.md` (Macros). Where they disagree with this file, this file wins. Written 2026-11-22 when the module was built.

**How to use it.** Before changing Macros, read the rules of the parts you change. After the change run `scripts/test.sh` and check every affected rule by its Verify line.

Code abbreviations: MM = `Macros/MacroModel.swift`, MR = `Macros/MacroRunner.swift`, MO = `Macros/MacrosModule.swift`, MP = `Macros/MacroPanel.swift`, ME = `Macros/MacroEditor.swift`, SM = `App/StatusMenu.swift`, EP = `Core/EventPoster.swift`.

## 1. Rules

### A. The module
- **MAC-01** A module of its own, "Macros" (both languages), on by default, Settings tile blue with `keyboard.badge.ellipsis`, summary "Fills forms for you: text, keys, waits and files, in order, in the app in front. Stops if you switch apps, click or press Esc." While no macro runs it has no timer, observer or event monitor; the editor window and the list panel exist only while open. Needs Accessibility (already granted to Penknife); without it a run shows the permission alert (category "Macros").
- **MAC-02** Shortcuts: the list ⌃⌥M (Settings › Macros › Shortcut, and Settings › Shortcuts); each macro may have its own (recorded in the editor, stored as `KeyboardShortcuts_macro.<id>`). A deleted macro's shortcut is reset. Module off → all of them are disabled.
- **MAC-03** Settings › Macros: "New macros type text by" Pasting / Keystrokes (default Pasting, `macros.typesText`); "N macros" with "Edit Macros…"; footer "Macros are stored on this Mac, only for you. Don't use them for passwords." Alerts can be hidden under General like the others (category "Macros").

### B. A macro and its steps
- **MAC-05** A macro: name, steps, "Type as" Paste / Keystrokes, data rows, counter, apps it was used in. Steps: Type Text (with variables), Key (Tab, Return, Esc, arrows, Space from a menu, or any key/combination recorded, e.g. ⌘A), Wait (ms, 0–60 000, default 300, step 100), Wait for Me, File (paste the file, or type its path via ⌘⇧G + path + Return for Open dialogs), Pinned Item (follows one pinned clipboard text).
- **MAC-06** Name (user, 2026-11-22: "el nombre por defecto se debería poder borrar al dar click automáticamente, y click por fuera lo vuelve a poner"): a default name ("New Macro", "New Macro 2") clears when the field gets focus and shows as the placeholder; leaving it empty puts it back. An empty name is never saved. Verify: MAC-06 test + live.
- **MAC-10** Variables in Type Text: `{date}`/`{fecha}`, `{time}`/`{hora}` (system formats), `{n}` (counter, +1 on each completed run), `{random}`/`{aleatorio}` (6 random digits), `{clipboard}`/`{portapapeles}` (the clipboard's text when the run starts). Verify: MAC-10 test.
- **MAC-11** Unknown names and lone braces are typed as written. Verify: test.
- **MAC-12** `{ask:Name}`/`{preguntar:Nombre}`: before the run a small glass prompt "Details for “macro”" asks each question once, prefilled with the last answer; Return runs, Esc or a click elsewhere cancels (nothing runs). Verify: test + live.
- **MAC-13** Pinned Item step: at run time the text of the pin it follows (by id, not position: copying or reordering doesn't break it). If the pin is gone (deleted, unpinned, not text, or Clipboard History off) it is asked in the same prompt, prefilled with the last value typed there (only plan B values are remembered; a found pin's text is never copied into Macros.json), with the note "The pinned item is gone. Type the value for this run." Updating the pin: CB-34.

### C. Data rows
- **MAC-20** Data tab = a table (variant A + empty state C, user 2026-11-22: "no entiendo cómo usar la sección de data… no tiene usabilidad"). Header cells are the column names (blue `curlybraces`), edited in place; each is a variable `{name}` (case-insensitive) for Type Text steps. Hint above: "Each run uses the next row. Use {a} or {b} in a “Type Text” step." `+` in the header adds a column ("column", "column 2"…); right-click a header: Remove Column. Rows: number, cells (plain text fields, Tab moves on), `minus.circle` Remove Row, "Add Row" below; right-click: Use Next / Remove Row; clicking the number makes it the next row. Footer: "Repeat rows" switch, "Next: row x of y", "Start Again", and the caption "Names can have spaces; { and } aren't allowed. Renaming a column updates the steps." Verify: live.
- **MAC-21** Each completed run uses the next row (▶ and an accent background mark it); a stopped run keeps the same row for the next try. The panel row shows "N steps · row x of y". Verify: test.
- **MAC-22** "Repeat rows" (user, 2026-11-22): on (default) → after the last row the next run starts at row 1; off → the macro doesn't run and the alert "“macro” didn't run — No rows left. Turn on “Repeat rows”." shows. "Start Again" sets the next row to 1. Verify: test.
- **MAC-23** Removing a row before the next one keeps the same next row; the next row is clamped to the table. Pasting a whole table (empty state) starts at row 1. Verify: MAC-25 test.
- **MAC-24** Renaming a column (applied when you leave the field or press Return) replaces every `{old}` in the Type Text steps with `{new}` (case-insensitive) and the {} menu follows. Names: spaces allowed, `{` `}` dropped as you type, ends trimmed; empty or repeated (case-insensitive) names show red and aren't applied. Verify: test.
- **MAC-25** Pasting into a cell a block with tabs or line breaks (copied from a spreadsheet) spreads it right and down from that cell (replacing that cell, not appended to its text), adding rows as needed; cells past the last column are left out. Known: right-click on a cell or header text shows the text menu; Remove Column / Use Next are on the `{}` icon and the row number. Verify: test + live.
- **MAC-26** Empty state (no columns): `tablecells`, "One Row for Each Run", "Paste a table from Excel, Numbers or Sheets, or start an empty one. Then use {email} in a “Type Text” step.", an example table, "Paste Table" (prominent; reads the clipboard, first row = column names, tabs/semicolons/commas; empty or repeated names get a number; nothing usable → "Copy a table first: its first row names the columns.") and "Empty Table" (one column, one row).

### D. Create from text
- **MAC-30** "Create from Text…" sheet, mode KEY=value: each line → key, Tab, value, Return (split at the first "="; blank lines skipped). Verify: test.
- **MAC-31** Mode "One text per line": each line a text, Tab between them. The sheet shows "N steps will be added"; the steps are appended. Verify: test.

### E. Storage, export, import
- **MAC-40** Saved to `~/Library/Application Support/Penknife/Macros.json`, folder 0700, file 0600, written 0.4 s after the last change (and when the editor closes). Verify: test.
- **MAC-41** A file that can't be read is moved aside as `Macros (unreadable <time>).json`, never written over. Verify: test.
- **MAC-42** Export (one macro from its context menu, or "Export All…") writes JSON with what the macros do; run state (counter, row, apps, answers, last pinned values) stays on this Mac. Verify: test.
- **MAC-44** Import safety (security review 2026-11-22): run state in the file is dropped, waits clamped to 60 s, key codes outside 0–127 become Tab; more than 500 steps, 10 000 characters in a text or 10 000 data rows → "These macros are too big to import."; macros that paste/type files, press ⌘ shortcuts or type the clipboard ask "Import macros from someone else?" first. Export drops linked pins (id and label). Verify: test.
- **MAC-43** Import: new ids; a macro with the same name asks "Keep Both" (renamed "Name 2") or "Replace" (keeps the existing id and shortcut). Verify: test.

### F. The list panel
- **MAC-45** ⌃⌥M opens a glass panel like the clipboard's (480 pt wide, rows 28 pt, height set on open, 300–680 pt and ≤ 72 % of the screen, same position setting). Search "Search Macros" (name only). One list in the editor's order (the "In <app>" / "All" groups were removed, user 2026-11-22: "no me gusta que se separen los macros por la última app usada, se ve raro"; the apps a macro ran in are still recorded). Row: ▶, name, "N steps", its shortcut. Footer "↩ Run ⌘E Edit ⌘N New". Keys: ↑↓, Return runs, Esc closes, ⌘E edit, ⌘N new, ⌘D duplicate, ⌘⌫ delete (asks). Empty: "No Macros" + "Create one to type text and keys for you." + "New Macro". Click elsewhere closes it.
- **MAC-46** Running from the panel: it closes, the app you were in keeps the keyboard, the run starts 0.15 s later.

### G. Running
- **MAC-50..52**: clipboard rules CB-34, CB-35 (tests named MAC-50..52).
- **MAC-55** Text goes in by pasting (default): the text is put on the clipboard marked `org.nspasteboard.TransientType` (Clipboard History skips it) and ⌘V is sent; the next clipboard change waits 0.15 s so the app reads the right text. Keystrokes mode types the text as key events (16 UTF-16 units per event, newlines as Return).
- **MAC-56** The run waits (≤ 1 s) for the shortcut's modifiers to be released, then runs the steps with 40 ms between them, in the app that was in front when it started.
- **MAC-57** Stops at once (alert "Macro stopped", with the reason) when another app comes to the front, on any click, or on Esc pressed by the user (Penknife's own Esc keys are marked, EP `marker`, and ignored). Nothing more is typed. Before every non-wait step it also checks that the same app is in front, and stops ("A password field is active") when secure input is on (a password field, or an app like Terminal with Secure Keyboard Entry: a known limit, it blocks macros while that is on; MAC-78 lets a macro skip it).
- **MAC-58** Wait for Me: the run pauses; clicks and typing are allowed; the list shortcut or the macro's own shortcut continues it; Esc stops it. It continues only if the same app is in front, else it stops ("Another app came to the front").
- **MAC-60** The user's clipboard (every type of every item) is put back when the run ends or stops, 0.3 s after the last paste, unless the user copied something during the run (their new copy is kept). Promised types (file promises) are not snapshotted. Verify: test.
- **MAC-62** Menu bar while running (indicator A, user 2026-11-22: "el triángulo para el indicador"): the Penknife logo becomes a blue `play.fill`; while waiting, a blue `hand.raised.fill` with the tooltip "Waiting… press the shortcut to continue"; the status dots stay. VoiceOver value "Running macro <name>" / "Macro <name> is waiting. Press its shortcut to continue." A finished run shows nothing. The jiggler holds off while a macro runs.

### H. The editor
- **MAC-72** Icon per macro (user, 2026-11-22: "quería poder agregarles un emoji o un color, como un ícono … igual el clipboard, misma funcionalidad, mismo componente. En el edit podría fijar esos elementos"): the same `IconEditor` and `PinIconView` as the clipboard pins (CB-33): one letter or emoji, a color, or neither (= ▶). Set it with the 40 pt tile left of the name in the editor (ux-ui-designer, 2026-11-22, for the user's "no es tan intuitivo saber dónde cambio el emoji"): on hover (only; at rest a plain gray tile, never focused when the window opens) an accent ring and a `pencil.circle.fill` badge; tooltip and VoiceOver "Change Icon…" / "Cambiar icono…", hint "Opens the icon editor"; right-click on the tile or the name: "Change Icon…"; pointing-hand cursor only while the tile is empty. Popover caption "Without a letter or color, ▶ is shown" / "Sin letra ni color se muestra ▶"; the field's placeholder is "Aa", 72 pt (clipboard too). Shown 16 pt in the editor's sidebar and in the ⌃⌥M list (instead of ▶). Saved and exported with the macro (`icon`).
- **MAC-71** Every Penknife alert (delete, import, export errors here; also clipboard Clear and the recording end questions) puts its buttons on the Touch Bar (`NSAlert.addTouchBar()`, Core/AlertTouchBar.swift): Cancel on the left, the action on the right, red when destructive (Delete, Discard), else the accent color. Penknife's own bar steps aside for it (TB-43); before, the bar went black (user, 2026-11-22: "no salen los botones en el Touch Bar de Cancel o Delete"). Delete buttons are destructive (red) in the alert too and never the default (Return doesn't delete; ux-ui-designer). Verify: manual — delete a macro: the Touch Bar shows Cancel and a red Delete.
- **MAC-73** Autosave is said once (user, 2026-11-22: "esperaba saber que quedó guardado mi macro y no que debo asumir que quedó"; asked for my view, agreed to "bueno"): the window subtitle "Changes are saved automatically" / "Los cambios se guardan automáticamente" (static, `.navigationSubtitle`), no per-save toast. Approved by `ux-ui-designer` (stays when another macro is chosen: it is on the split view).
- **MAC-70** Own window "Macros" (700×540, min 680×420 — at 620 the detail was cut on the right, QA 2026-11-23 —, position and size remembered, never resized by its content — clicking Data used to make it fill the screen, user 2026-11-22; variant A, user 2026-11-22): macros on the left (+, −, ··· with Import… / Export All…; right-click: Duplicate, Export…, Delete…), the chosen macro on the right: name, Shortcut recorder, "Type as" Paste / Keystrokes, Steps / Data. Steps are 36 pt rows: drag handle, kind symbol, the step's editor, ··· (Duplicate, Delete); right-click adds Move Up / Move Down; VoiceOver actions Move up / Move down / Duplicate / Delete. "Add Step" menu and "Create from Text…" below. The {} menu inserts a variable (and data columns) at the end of the text.

## 2. Open decisions and known limits
- Variables are inserted at the end of the text, shown as plain text (no blue tokens yet).
- Web upload buttons don't take a pasted file (browser limit); Type Path works in Open dialogs.

## 3. Rejected (do not rebuild)
- Script steps and "Run an Apple Shortcut" steps (user, 2026-11-22: "sin script").
- Recording keystrokes (needs Input Monitoring, works like a keylogger).
- **MAC-74** Editor bugs (user, 2026-11-23: "poner un emoji … lo selecciono y lo pongo y no se pone … la ventana se queda abierta"; "si necesito pegar un texto que tengo en el clipboard … le doy click pero no se pone, tengo que presionar cmd + v"; "los campos de texto o de tiempo no se les puede quitar el foco"; "lo más grave es no poder seleccionar el elemento que quiero del clipboard"): (a) the icon popover is AppKit's and stays while the Emoji & Symbols viewer has the keyboard, so the first pick sets the icon, also after searching in the viewer (user, 2026-11-23: "al buscar un emoji … y al seleccionar el buscado, no lo pone. eso no sirve"; NOT fixed: the viewer's search can't reach a menu bar app, see DECISIONS; option asked to the user); Esc or a click elsewhere in the window closes it. (b) Choosing an item in Clipboard History while a Penknife window (the editor) had the keyboard pastes into it at once, at the caret of the field that was being edited. (c) A click outside the field being edited lets the focus go (text, ms, name). Build 366: QA passed (a), (c), the pin menu works; (b) caret kept, (d) nothing focused = no-op: all PASS (QA 2026-11-23). NOT tried by the user yet.
- **MAC-75** Emoji icons are never clipped (user, 2026-11-23: "los íconos más grandes, se cortan un poco", screenshot of the editor sidebar at 16 pt): `PinIconView` draws an emoji at its own size (`.fixedSize()`), centered in the square, everywhere it is used (sidebar, ⌃⌥M list, clipboard rows, header tile). Build 368; QA passed (zoomed, 4 places).
- **MAC-76** New steps go below the step you are on (user, 2026-11-23: "si en el macro tengo 5 elementos y estoy en el elemento 3 … cuando agregue un elemento nuevo, aparezca debajo … si no tengo seleccionado ningun elemento, aparece al final"). Clicking a row or editing one of its fields (text, ms) selects it (system unemphasized selection color behind the row, `ux-ui-designer` 2026-11-23); Add Step and Create from Text… insert right below it and the new (last) step becomes the selected one, so adding again keeps the order. Nothing selected (a click on the empty part of the list, another macro chosen, or the selected step deleted) → at the end. Selection is not saved. Verify: test "MAC-76"; manual — 5 steps, click step 3, Add Step › Wait: the wait is step 4.
- **MAC-77** A new step is brought into view (user, 2026-11-23: "si en el macro estoy en la parte de arriba, el cuadro tiene scroll, y no tengo ningún elemento seleccionado, al agregar un elemento nuevo, debería hacer foco en ese elemento, entonces el scroll se baja"). After Add Step or Create from Text…, the list scrolls (minimal, 0.2 s) so the new selected step is visible, wherever it was inserted. Verify: manual — a macro with more steps than fit, scrolled to the top, nothing selected, Add Step › Wait: the list scrolls down and the new wait is visible and selected. Build 378: QA passed 1–3, delete; drag not testable by QA. NOT tried by the user yet.
- **MAC-78** A macro can be allowed in password fields, at the user's own risk (user, 2026-11-23: "al ejecutarlo dice a password field is active y quiero quitar esa restricción, entiendo que puede ser inseguro pero quiero quede bajo responsabilidad del usuario"; per macro, chosen by the user; "quiero que cuando lo actives, salga un disclaimer para decir que no es nuestro problema"). Checkbox "Allow in password fields" / "Permitir en campos de contraseña" in the editor, on its own line right under "Type as", aligned right (a run setting, `ux-ui-designer` 2026-11-23; in the same row it made the detail wider than the window and cut it, QA), off by default. Turning it on shows an alert first: "¿Permitir en campos de contraseña?" — "Esc no la detendrá ahí; haz clic o cambia de app. Lo usas bajo tu propia responsabilidad; Penknife no se hace responsable de lo que escriba." (secure input hides keys from Penknife's monitor; a click or switching apps still stops it); Permitir (not red: red = delete) / Cancelar (the default, Return); turning it off asks nothing. No mark in the list (the checkbox is enough). When on, MAC-57's secure-input stop is skipped for that macro only; the other checks (same app in front, click, app change) stay. Not exported (an imported macro is always off). Verify: test "MAC-78"; manual — with a password field focused, a macro with it off stops ("A password field is active"), with it on it types.
- **MAC-79** Copy and paste several steps, within a macro or to another (user, 2026-11-23: "me gustaría poder copiar y pegar varios elementos de un macro a otro o dentro del mismo macro"; proposal accepted "yep"). Selection as in Finder: click selects one, ⌘-click adds or removes one, ⇧-click selects the range from the last clicked step; editing a field selects its step. ⌘C or right-click › Copy copies the selected steps (right-click on an unselected row: that row); ⌘V or right-click › Paste (also on the empty part of the list) pastes them with new ids below the lowest selected step, or at the end (MAC-76), selects them and scrolls to them (MAC-77); they can be pasted again. While a text field is being edited, ⌘C/⌘V are the field's. Copied steps stay inside Penknife (not the system clipboard, so the clipboard history and what the user copied are untouched) until Penknife quits. Steps tab only. Verify: test "MAC-79"; manual — macro A: click step 1, ⇧-click step 3, ⌘C; macro B: click step 2, ⌘V → the three steps are 3–5 of B, selected. Build 382: QA passed all (mouse clicks, ⌘C/⌘V sent to its copy only, system clipboard untouched). NOT tried by the user yet.
